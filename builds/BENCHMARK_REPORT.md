# Benchmark 02 — отчёт исполнителя

## Подход и причины
- **Стек:** Vite 8 + TypeScript + Three.js 0.186 (WebGL2), версии зафиксированы `package-lock.json`. Полноценное 3D с фиксированной ортографической изометрией (yaw 45°, наклон ≈41.5°): даёт настоящие тени, движущийся свет дрона, повороты моделей вместо 8-ракурсных спрайтов и дешёвые программные правки.
- **Ассеты — код:** персонаж, монстр, дрон и всё окружение строятся процедурно из параметрических спецификаций (`src/assets/*`), текстуры генерируются из seeded-шума (albedo/normal/roughness). Исходник = «общее описание»: правка спецификации согласованно меняет модель со всех сторон, ручного редактирования человеком нет.
- **Анимации:** процедурные на суставном риге с двухзвенным IK (руки держат оружие, ступни монстра «заякорены»), поэтому переживают изменения модели/экипировки.
- **Геймплей отдельно от визуала:** детерминированная симуляция 60 Гц (`src/sim/*`) без DOM/three.js — те же правила в vitest и в браузере; рендер, анимации, эффекты и свет только читают состояние.
- **Машинный интерфейс:** `window.__game` — state/errors/events/visibility (с причиной и перекрывающим укрытием)/coverage (пиксели ID-прохода)/anim/fxStats/lighting, pause/step/reset, move/aimAt/fire, worldToScreen, debug (turntable, respec, zoom, focus, drone, fx, post).
- **Проверка:** Playwright (`playwright-core` + системный Chrome headless на GPU) с **реальными** событиями клавиатуры и мыши + vitest. Каждый этап упакован скриптом `scripts/package-stage.mjs`: архив распаковывается в отдельную папку, запускается его собственный `serve.mjs`, прогоняется весь e2e этапа; `source.zip` распаковывается отдельно → `npm ci` → `npm run build` → `npm test` (во всех 5 случаях пересборка дала идентичные хэшированные ассеты).

## Этап 07: пайплайн ассетов
- **Подход:** headless Blender 4.5.14 LTS (портативная сборка скачивается автоматически) + Python-генераторы по JSON-спекам (`assetgen/`) → GLB. Геометрия детерминированно строится из параметров; AO, маски рёбер и полостей запекаются в вершинные цвета; материалы назначаются в рантайме по имени слота из палитры спеки. Новые модели посажены на существующие суставы/IK, поэтому анимации и геймплей не менялись. Генеративные image→3D-модели не использовались: процедурный пайплайн даёт программную изменяемость (правка спеки → 2–3 с на ассет) и полную автономность без внешних ключей.
- **Включение:** P/Esc → меню паузы (или `?all=new&cam=persp`). Камера «слабая перспектива» — тот же фиксированный азимут/наклон, без вращения, объектив 14° ≈ 98 мм (ползунок 6–30°).
- **Дорого:** визуальная калибровка, а не моделирование — маска износа рёбер «растекалась» по плоским граням (скалы и колонны светлели) и потребовала расчёта кривизны и внутренних вершин граней; освещение сцены рассчитано на очень тёмные альбедо; монстр — 3 итерации формы. **Дёшево:** смена экипировки через спеку (2.4 с перегенерации, видно со всех 8 ракурсов, 0 ручных правок), перекраска — вообще без Blender.

## Где создание/изменение ассетов было дорогим
- **Монстр** — самое дорогое: 3 переделки анатомии (тёмный глянец → «гусеница с шаром» → гранёный хищник), затем охота за «белёсой вуалью» при попадании (оказалась bloom от перегретых эмиссивов, а не свет/оверлей).
- **Стойка игрока:** IK-руки не доставали до цевья (ошибка 0.28 м) — пришлось перенести винтовку на позвоночник, развернуть корпус и удлинить руки.
- **Эффекты** под изометрию потребовали гиперболизации масштаба и отдельного тюнинга дыма.
- Плановое изменение экипировки (этап 02) и смена модели/экипировки (этап 03) были **дешёвыми**: одно поле спецификации, 0 ручных правок ракурсов.

## Найдено и исправлено по ходу
- rAF-метка времени в headless Chrome «застывала» после долгих синхронных вызовов → цикл переведён на `performance.now()` с этапа 02. В билде 01 дефект латентный (в обычном браузере не проявляется), проверки 01 он не провалил; отдельная ревизия 01 не выпускалась.
- Пауза теперь замораживает и визуал (эффекты/анимации), что делает кадры воспроизводимыми (с этапа 04).

## Что осталось непроверенным
- Только Chrome на Windows с RTX 4090 (ANGLE/D3D11, headless). Firefox/Safari, слабые/интегрированные GPU, HiDPI-экраны, мобильные — не проверялись.
- Художественное качество оценено исполнителем по кадрам; человеческой приёмки нет.
- Долгие сессии (утечки памяти за десятки минут) не профилировались; проверено лишь отсутствие утечек объектов FX после серий стрельбы.
- Звук отсутствует (не входил в требования).

## Запуск
Распаковать любой архив → `node serve.mjs` (или `run.bat` / `sh run.sh`) → http://localhost:8080/. Управление: WASD, мышь, ЛКМ, R — перезапуск, F3 — debug. Подробно — `RUN.md` в архиве.
